# AstroImageNow v1.11 — Target, date and site planning

Baseline: v1.10 merge `221f2d2dc91556c296b7f22d0d66457047719919`. Implementation branch: `codex/target-planning`. Date: September 19, 2026.

## User outcome

The forecast now leads into **What could I image?** A **Plan targets** shortcut opens a searchable, curated deep-sky catalog for the selected observing site and night. Another date can be explored without inventing a future weather forecast. A target inspection shows its geometric window, highest altitude in darkness, Moon geometry, rough framing, filter and site advice. A target assignment can be saved locally with its date, site, rig, filter and minimum altitude.

This is the first target-planning increment from the master handoff. It does not complete the full v3 roadmap, claim integration-time predictions, or treat good celestial geometry as safe weather.

## Reconciled inputs and architecture

- Read the full master handoff and the authoritative current rig record before implementation. The latter's September 18 OAG installation supersedes the handoff's older guide-scope arrangement: Elite Drawer OAG + ASI120MM Mini installed, optical spacing still awaiting field verification.
- Only L-Pro is confirmed as an owned imaging filter. It is a broadband filter; no owned dual-band filter was inferred. Unfiltered is an explicit baseline. C8/8SE lunar/planetary commissioning remains distinct from the Z73 deep-sky workflow.
- 31 curated targets from pinned OpenNGC release `v20260501`, with CC BY-SA 4.0 attribution/license, imported rows, source-field provenance and an offline generator. Authored curation flags complex/component size ambiguity. No guessed coordinates or exact home data are committed.
- Astronomy Engine v2.1.19, MIT, is vendored for offline Sun/Moon/J2000 geometry. A single local solar implementation supplies dashboard darkness and target calculations. The weather dashboard retains hourly provider samples; target geometry uses 10-minute samples.
- Nominal Z73/ASI533 field is 1.51° square, 1.80″/pixel. The full M31 disk and M45 cluster exceed it. Framing assumes deliberate camera rotation and excludes edge cropping/optical defects; four ambiguous complex entries withhold a fit claim.
- Moon advice responds to altitude, illumination, separation and object/filter type. Site advice uses saved Bortle and target sensitivity. Both are explicit heuristics; candidate ordering is not a calibrated imaging-success score.
- Planner preferences and assignments use `astroImageNowPlannerV1`, separate from credentials, site settings and the forecast snapshot. Assignments contain IDs and planning choices, not credentials or coordinates.

Full licensing, coordinate contracts, formulas, heuristic thresholds and limitations: [data/method notes](../../data/README.md). Source hashes: [provenance](../../data/provenance.json).

## Limits and next coherent increment

Current windows use altitude, darkness and Moon, with a separate night-level weather banner. They do not yet intersect each target window with the hourly cloud/transparency forecast, compare Home/JGAP side by side, estimate required integration time, or model obstructions/meridian flips. Those distinctions are visible in the UI. Plans remain device-local; a site-profile deletion removes that site's assignments from the displayed list.

Next: intersect target windows with actual forecast coverage and expose the limiting reason for each interval, then compare the same target/date across Home and JGAP without conflating missing data with good conditions. Preserve the current geometric planner for beyond-forecast/offline use. C8 lunar/planetary target logic, sensor integration, packing/startup/shutdown workflows, synchronization and ChatGPT integration follow as separate bounded increments.
