# AstroImageNow v1.13 — Full-week estimates, Imaging Targets and observing history

Baseline: v1.12.0, `c2b7704546421729163127d884b1d38c74d5b1cc`. Branch: `codex/week-outlook-target-advisor`. Work began September 19, 2026.

## Result

Later nights now use available Foreca/Open-Meteo meteorology for a normalized conditions score, with a small **≈** marker and an optional explanation. Seeing and transparency remain unknown beyond their actual coverage. The top score has fixed weights independent of telescope, target, camera, filter and Moon. Moon now guides target selection, and its geometry is computed locally for the entire week. Hazard overrides, incomplete-input checks, stale-cache treatment and provider isolation remain intact.

**Imaging Targets** adds quiet red target rings while preserving the approved graphite/papaya palette. Up to three explained subject/rig/filter/window choices can compare deep sky versus Moon/planets, constrain to one mode, or honor the selected setup. Defaults use existing filter choices; optional exploration includes planned L-Ultimate and proposed UV/IR-cut. Manual filter selection has short context-aware advice. Suggestions are deterministic local rules, not remote LLM calls or a claim to know unrecorded sessions. Detailed formulas, ownership states and source links are in [the method notes](../../data/README.md).

The first observing journal records real user-entered sessions, supports edit/removal/undo and JSON backup, and modestly prioritizes revisits. Historical sessions survive removal of a saved observing site. No entries means history is unknown. All state remains local to this browser/device; the iPhone and desktop are not synchronized. Existing keys, saved sites and plan IDs are preserved. No sample session is included in production data.

## Continuation

Next substantial layers are backup import and cross-device journal reconciliation, useful planet apparent size/time-sensitive events, verified commissioning and filter paths, and an optional conversational AI layer over the existing explicit data contracts. The glass/transparency effect can be refined in CSS on the current PWA; no new design account or app is required for this release.
