# AstroImageNow v1.10 — Foreca and forecast reliability

Date: September 19, 2026. Baseline: v1.9 commit `57131942eb488bbb0b3d536242707d78d414ff41`, preserved locally as `codex/baseline-v1.9-2026-09-19`. Implementation branch: `codex/foreca-reliability`.

## Decision and confirmed diagnosis

Jason explicitly requested Foreca as an included, working provider and entered a new Weather API token directly into the app. This supersedes the initial assessment's proposed deferral of Foreca. Foreca remains primary in the existing Foreca-with-backup setting. Open-Meteo remains an explicit backup or selectable alternative.

With the newly saved token, v1.9's `pfa.foreca.com` host returned HTTP 401 and directed the client to `weatherapi.foreca.net`. Requests from the same deployed browser origin to that current host succeeded: current conditions HTTP 200, hourly weather HTTP 200 with 168 rows, and hourly air quality HTTP 200 with 84 rows. The token never entered chat, a source file, a request URL, or a diagnostic export.

This establishes the cause of the reproduced failure with the new token. The earlier iPhone incident did not have captured response logs, so its exact historical cause remains unproven.

Official contracts used: [Foreca point forecasts](https://developer.foreca.com/docs/point-forecasts) and [air quality](https://developer.foreca.com/docs/air-quality). The provider boundary uses bearer authentication, full weather fields, explicit Fahrenheit/mph requests, UTC timestamps, and converts precipitation from millimeters to inches.

## Shipped behavior

- Independent astronomy, weather, and Moon outcomes; bounded requests and stale-result rejection on refresh/site changes.
- Foreca hourly weather survives optional current-condition or air-quality failure. Backup selection and failure reasons are visible.
- Invalid/missing values remain unknown; missing weather or Moon cannot create a false complete GO assessment.
- Headline astronomy scores now retain the hard caps used by hourly scoring. Significant weather hazards also affect the operational verdict and night cards.
- Up to seven selectable nights use the actual available provider timestamps. Nights beyond Astrospheric coverage remain weather-only; their missing astronomy scores are not fabricated.
- Saved forecasts are tied to site/source and visibly stale after refresh failure, restored on reload, or older than three hours. Only one last-used context is retained. Staleness updates while visible or when returning to the app.
- Night selection persists by local calendar date; best-window duration stops at the last dark hourly sample.
- Diagnostic fields include build version, worker control/waiting status, source, per-provider outcome, retrieval time, coverage, model time, credits, and sanitized errors. They exclude credentials, coordinates, and site names.
- Update controls support explicit application of a waiting service worker. Shell caching is restricted to this app; unrelated caches and provider responses are not touched.
